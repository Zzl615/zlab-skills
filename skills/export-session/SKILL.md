# Export Session

将本次对话整理成一份可直接保存的 Markdown。目标是让任何人日后拿到这份文档，不需要重读对话，就能理解发生了什么、为什么这么做、结果如何。

## 整理逻辑

**按轮次拆分，而不是按话题归类。** 每一轮（用户说了什么 → AI 回答了什么 → 实际执行了什么 → 结果如何）是最小单元。保持这个粒度，读者才能追踪决策的先后顺序和因果关系，而不只是看到结论。

**保留原始信息，尤其是报错。** 整理不是美化——错误信息、失败路径、走弯路的过程同样有价值，它们说明了为什么最终方案是现在这样。

**代码和命令用代码块。** 这不是格式规范，是可读性需求：混在正文里的命令很难被复制执行。

**对话很长时合并重复轮次。** 如果连续几轮都是"小修改 → 验证"的循环，合并为一轮并注明轮次范围，避免文档比对话还啰嗦。

完整的输出模板见 `references/template.md`。

## 执行流程

1. 回顾对话，识别轮次边界（一次用户输入 = 一轮开始）
2. 按模板生成完整 Markdown，输出到对话中
3. 调用 `scripts/save_session.py` 保存文件

   ```bash
   # 用户指定路径时：
   python scripts/save_session.py --path <用户给的路径>

   # 用户没指定时（脚本自动生成 session-YYYY-MM-DD.md）：
   python scripts/save_session.py
   ```

   将生成的 Markdown 内容通过 stdin 传入：
   ```bash
   echo "<markdown内容>" | python scripts/save_session.py --path ./session.md
   ```

4. 输出保存路径，告知用户完成

如果用户明确说不需要保存（如只说"整理一下看看"），跳过第 3-4 步。

## 边界情况

- **1-2 轮的短对话**：照常输出完整结构，Final Conclusion 写简短即可
- **纯探索性对话，无执行操作**：执行节写"无"，Final Conclusion 说明"本次为探索性讨论"
- **用户在触发时已给出路径**（如"整理后保存到 ~/notes/today.md"）：直接保存，不必再询问
